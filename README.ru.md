# Telegram My ID

<img src="assets/icons/telegram-my-id-128.png" width="112" alt="Иконка Telegram My ID">

[English](README.md) · [Русский](README.ru.md) · [Español](README.es.md)

**Небольшой Telegram-бот с полноценным окном на Mac.**

Кремовый фон, цветные карточки и объёмная иконка. В одном окне — запуск и остановка,
статус, журнал событий, настройка подключения и локальный предпросмотр команд.
Интерфейс приложения — на русском; ответы бота — на русском, английском, испанском и корейском.

![Главное окно Telegram My ID](assets/screenshots/overview.png)

На скриншоте бот остановлен. В предпросмотре используется вымышленный Alex Example
с ID `100000001`; личные данные из Telegram и настоящие токены не показаны.

## Запуск

```sh
make setup
make doctor
make local
```

Готовые файлы: `dist/TelegramMyID.app` и `dist/TelegramMyID-macos-<архитектура>.zip`.
Приложение можно открыть двойным щелчком. Открытие окна не запускает бота автоматически.

1. Откройте **Настройки** и выберите свой `.env` с `TELOXIDE_TOKEN` либо введите токен
   на время сессии. Его выдаёт @BotFather. В диалоге macOS Cmd+Shift+. показывает скрытые файлы.
2. Выберите папку данных. Для прежней базы укажите старую `src/db/data`.
3. Нажмите **Сохранить пути**, затем **Запустить бота**.
4. После подтверждения подключения откройте бота в Telegram и отправьте `/start`.

Остановка — кнопкой или Esc. Cmd+Enter запускает остановленного бота.
В **Настройки → Закрытие окна** можно включить продолжение работы после закрытия приложения.
Без этой настройки закрытие останавливает бота. Повторное открытие подключается к работающему процессу.
Используется long polling; существующий webhook автоматически не удаляется.
Один токен не следует одновременно запускать в нескольких polling-клиентах.

## Возможности

| В приложении | В Telegram |
| --- | --- |
| Запуск и остановка в отдельном потоке | `/start` — приветствие и выбор языка |
| Имя и ID бота после проверки Telegram | `/info_user` — свой ID и профиль |
| Последние 150 событий в памяти | `/language` — RU, EN, ES, KO |
| Скрытый ввод токена, выбор `.env` | `/help` — список команд |
| Сохранение путей подключения | `/random_number` — число в диапазоне |
| Предпросмотр семи команд без сети | `/random_choice` — вариант из списка |
| Сохранение прежнего JSON-формата языков | `/test` — диагностика |

Бот показывает информацию отправителя, а не ищет закрытые данные произвольных аккаунтов.

## Токен и данные

Настройки хранят только пути к `.env` и папке данных. Токен туда не записывается.
Ручной токен остаётся в памяти рабочего процесса до остановки бота. `.env` читается заново при запуске бота; необязательный `TELOXIDE_PROXY` также поддерживается.
Журнал не сохраняется автоматически в файлы; токены скрываются в диагностике.

Стандартные пути на Mac:

```text
~/Library/Application Support/TelegramMyID/settings.json
~/Library/Application Support/TelegramMyID/data/languages.json
```

Данные не переносятся автоматически. Прежнюю базу можно подключить выбором её папки.
Повреждённый JSON выдаёт ошибку и не затирается пустой базой. Сохранение выполняется
через временный файл. Блокировка папки предотвращает одновременный запуск с одной базой.

## Разработка

Нужны Rust 1.94+ и Xcode Command Line Tools. Node.js/NVM не нужны для работы приложения;
Node.js и системный `sips` используются только при повторном экспорте иконок.

| Команда | Действие |
| --- | --- |
| `make` / `make dev` | Разработка: собрать и открыть окно |
| `make build` | Собрать GUI + CLI и нативный установщик |
| `make run` | Открыть готовую сборку |
| `make start` | Собрать и открыть release |
| `make cli` | Консольный режим |
| `make check` | Форматирование, строгий Clippy и тесты |
| `make icons` | Экспортировать иконки |

Консольный бинарник сохранён:

```sh
RUST_LOG=info cargo run --locked --bin telegram-bot
```

Он читает токен из окружения или локального `.env` и по умолчанию использует
`src/db/data`. Переменная `TELEGRAM_MY_ID_DATA_DIR` задаёт другой путь. Ctrl+C останавливает бота.
Чтобы GUI и CLI использовали одну базу, укажите им одну абсолютную папку.

Сборка не включает `.env`, настройки и пользовательские базы. Подпись по умолчанию
локальная ad hoc; для существующего сертификата предусмотрена переменная
`TELEGRAM_MY_ID_SIGNING_IDENTITY`. Нотарификация и публикация не выполняются.
Сборка и запуск Windows/Linux не проверены; Windows-релиз не заявлен.

## Проверки и структура

`make check` проверяет команды, случайные функции, предпросмотр на четырёх языках,
валидацию и скрытие токена, сохранность базы, отмену, блокировку папки и цикл
подключения/polling/остановки через изолированный локальный API. Тесты не отправляют
сообщения в Telegram. Проверку работы с настоящим токеном отдельно выполняет владелец бота.

`src/desktop/` отвечает за окно; `src/runtime.rs` — за общий диспетчер;
`src/settings.rs` — за настройки; `src/bin/telegram-bot.rs` — за CLI.
Прежние application/domain/infrastructure/locales сохранены.

Шрифты Inter, Noto Sans KR и Noto Emoji входят в проект вместе с лицензиями в
[assets/fonts](assets/fonts). Исходник иконки и экспорты — в `assets/icons`.
Подробнее: [полная документация](README.md). Условия проекта: [LICENSE](LICENSE).


## Нативные установщики

Для текущих исходников: `make setup`, `make doctor`, `make local`. Последняя команда
собирает и открывает установщик; `make run` открывает готовую release-копию.
PowerShell: `./package.ps1 setup`, `./package.ps1 doctor`, `./package.ps1 local`.
GUI и headless входят в пакет; установленному приложению не нужны Rust и терминал.
Вне checkout CLI использует пользовательский каталог данных, если не выбран
`TELEGRAM_MY_ID_DATA_DIR` и отсутствует прежняя `src/db/data`.
Зависимости, пути DMG/EXE/DEB, команды и границы проверки: [docs/INSTALLERS.md](docs/INSTALLERS.md).


Фоновая работа, сохранение режима и остановка без окна: [docs/BACKGROUND.md](docs/BACKGROUND.md).
